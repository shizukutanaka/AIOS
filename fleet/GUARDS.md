# Fleet Guard Layer — 証拠整合性の監視（蒸留版）

> 旧 `agent-fleet` の GUARD_SUITE.md から、考え方と中核7層を蒸留したもの。
> 旧スイートは約45件のガードで構成されていたが、本統合では設計文書が
> 「証拠整合性層」と位置づける7層（L35–L41）のみを代表として持ち込んだ。
> 残りのガードと集約ランナーはアーカイブされる旧リポジトリに残る。

## 第一原理

**徹底した自動化とは、完了を自己申告ではなく証拠（オラクル）でのみ判定する
ことである。** 判定者（ボス）自身も判定されなければならない。
緑のステータスは「生きていると証明された」ときだけ緑である。

## 7層（持ち込み分）

| 層 | ファイル | 何を証明するか |
|---|---|---|
| L35 | `guard_trust_boundary.sh` | チャネル境界: エージェントが割り当てられた入出力チャネルを越境しない |
| L36 | `guard_resource_limit.sh` | 資源境界: VRAM/ディスク/時間の予算を超過しない |
| L37 | `guard_cross_agent_consistency.sh` | エージェント間で矛盾する主張がない |
| L38 | `guard_cross_layer_integrity.sh` | スイート自己整合性: 全ガードの self-test が GREEN |
| L39 | `guard_verdict_integrity.sh` | **判定整合性**: ボスの `verdict=OK/PASS` が物理オラクルの現実と一致する（捏造された承認がない） |
| L40 | `guard_evidence_integrity.sh` | **証拠整合性**: 引用された外部証拠（文献 ID 等）が実在し条件を満たす（幻覚引用がない） |
| L41 | `guard_boss_liveness.sh` | **判定者の生存**: ボスが凍結・欠落・汚染状態でない（凍結した判定者は verdict を出さないため、L39 では「沈黙」を捕捉できない） |

## メタ監査の教訓（なぜ L41 と鮮度監査が要るか）

過去に2件、「設定されているのに実体がない監視」が見つかった。いずれも
**phantom cron**（存在しないスクリプトを指す定期実行で、失敗しているのに
最終ステータス表示が正常に見えた）だった。

- 対策: 監視の実行マーカー（最終実行記録）の**鮮度**を別の監査が確認する。
  死んだ監視はマーカーを更新しないため、「マーカーが古い＝監視が死んでいる」
  として表面化する。
- 教訓: 「監視が設定されている」ことと「監視が生きている」ことは別物。
  後者は証拠（新鮮なマーカー）でのみ言える。

## 手動検証（証拠であって申告ではない）

```bash
# 各ガードのオフライン self-test（決定的）
bash fleet/guard_trust_boundary.sh --self-test
bash fleet/guard_verdict_integrity.sh --self-test

# 判定者が凍結していないか
bash fleet/guard_boss_liveness.sh   # BOSS_LIVENESS_OK を期待
```

各ガードは純粋な bash + grep で書かれ、`--self-test` は自分で作った
フィクスチャだけを走査する（本番状態を変更しない）。
